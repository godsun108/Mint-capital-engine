Express + TypeScript API preflight

A practical checklist and minimal implementation for a small Node.js API. This guide is free; you don't need to purchase anything to follow it.

1. Start with strict types

Install Express, TypeScript, and their types. Use Node.js 20 or later and enable strict checking.

npm init -y
npm install express
npm install -D typescript @types/node @types/express tsx
npx tsc --init

Set strict: true in tsconfig.json. Add "type": "module" to package.json. Configure module and moduleResolution as "NodeNext", and outDir as "dist". Use a src/server.ts entry point.

2. Add a minimal health route

import express from 'express';
const app = express();
app.disable('x-powered-by');
app.use(express.json({ limit: '100kb' }));
app.get('/health', (_req, res) => res.status(200).json({ ok: true }));
const port = Number(process.env.PORT ?? 3000);
if (!Number.isInteger(port) || port < 1 || port > 65535) {
  throw new Error('Invalid PORT');
}
app.listen(port, () => console.log('API listening'));

Run locally using npx tsx src/server.ts, then request http://localhost:3000/health. Expect HTTP 200 and {"ok":true}.

3. Validate configuration and errors

  • Use environment variables for credentials. Never commit secrets or print them in logs.
  • Fail fast if required configuration is missing or malformed.
  • Use centralized error handling; avoid returning stack traces to clients.
  • Set appropriate request-size limits and authentication for protected routes.
  • For public endpoints, consider rate limiting and abuse monitoring.

4. Test before deployment

  • Run npx tsc --noEmit and resolve all type errors.
  • Test the health route for HTTP 200 and expected JSON.
  • Test invalid input, missing credentials, and server failures.
  • Verify the deployment environment supplies PORT and all required secrets.
  • Check logs and monitoring, then document a rollback procedure.

5. Release gate

Do not consider the API ready solely because its health route works. Confirm functional tests, authorization, dependency security, error handling, monitoring, and recovery. Adapt these checks to your application and threat model.
