# EXECUTION WAVE 1

Goal: connect MINT to real-world actions that can produce settled USD.

## A — SELL
PRODUCT and SERVICE create legitimate offers and route buyers to a payment rail.
Machine work: package offer, generate fulfillment artifact, price/cost model, create draft listing/payment configuration.
Approval: publishing, external representation, pricing commitment where required.
Terminal state: SETTLED.

## B — COLLECT
RECEIVABLE operates only on genuine amounts owed.
Machine work: evidence packet, invoice draft, aging, reminder draft, reconciliation.
Approval: first external contact or other consequential communication unless separately authorized.
Terminal state: SETTLED.

## C — CLAIM
REFUND / REBATE / UNCLAIMED / GRANT locate legitimate candidates from authoritative sources.
Machine work: search, requirement extraction, matching, checklist, draft/prefill, deadline monitoring.
Approval: attestations, certifications and submission where required.
Terminal state: SETTLED.

## D — ACCESS
Financing remains a later adapter because liquidity must be evaluated with its liability: APR/fees, collateral, repayment, covenants and net proceeds.

## Immediate dependency
A live payment/accounting integration is required for end-to-end automated payment creation and reconciliation. Until connected, MINT can prepare execution objects but must not claim external objects or cash were created.
